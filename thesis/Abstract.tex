SQL:2016 introduced the \texttt{MATCH\_RECOGNIZE} clause for row pattern recognition, which searches ordered partitions of rows for a user-defined pattern. This matters wherever the significant information is a sequence of events rather than an isolated record, as in financial monitoring, sensor analytics, and e-commerce. Several database systems, including Oracle, Snowflake, Trino, and Apache Flink, now offer row pattern recognition, but Pandas has no native support. Analysts therefore simulate it with shifted columns, manual loops, and custom state handling, which makes the code longer and more error-prone. To close this gap, the proposed engine parses a SQL \texttt{MATCH\_RECOGNIZE} query, validates its row-pattern clauses, translates the pattern into finite automata, and runs the matcher over ordered DataFrame partitions. The supported scope covers \texttt{PARTITION BY}, \texttt{ORDER BY}, \texttt{PATTERN}, \texttt{DEFINE}, \texttt{MEASURES}, skip modes, output modes, quantifiers, alternation, grouping, anchors, exclusions, \texttt{PERMUTE}, and selected navigation and aggregate functions. The system was evaluated through five methods: correctness, SQL:2016 feature coverage, usability, performance, and scalability. Correctness compared the engine's output against Trino and Oracle on every benchmark query. Coverage was measured against Feature~R010, row pattern recognition in the \texttt{FROM} clause. Usability compared the declarative form against hand-written Pandas. Performance used the Amazon UK Products catalogue, with five pattern families over six sizes, from 100\,K rows to the full 2.2 million. Scalability used the Amazon Reviews~2023 corpus, up to 227.9 million rows. The engine reproduced the reference outputs row-for-row in all thirty benchmark cells. It also recorded the lowest average execution time: 0.16\,s against 1.04\,s for Oracle and 1.98\,s for Trino. Time and memory scaled almost linearly, and the engine stayed ahead of both databases to 227.9 million rows. These results show that \texttt{MATCH\_RECOGNIZE} in Pandas bridges SQL and Python workflows, and makes sequential analysis more readable and portable.
